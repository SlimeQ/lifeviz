# Background Baking

Use **Render Fixed Duration...** to bake a fixed-length silent video while designing another scene. Apply any pending Scene Editor changes so the preview contains the scene you want, choose a duration and FPS, and press **Add to Queue**. The setup window is nonmodal. Repeat for each scene; jobs run in submission order, with one active bake.

Each submission captures the preview's authored layers, source configuration, simulation/animation settings, resolution and aspect ratio, quality, and output folder. Changing the scene, quality, or folder afterward affects new submissions only. Output names include a unique suffix to prevent collisions with another bake or live recording.

Open **Bake Queue...** to see status, frame count, elapsed time, ETA, and output path. **Cancel bake** removes a waiting job or requests cancellation after the active frame and saves partial output. Encoder finalization can take additional time. A failed job is reported and the next queued job proceeds. **Open diagnostics** opens the retained job folder containing `worker.log`, the captured scene, and the request, so the exact error can be investigated. **Open output folder** opens that job's destination. Closing the queue window leaves work running, and reopening it restores the same jobs and history.

The queue belongs to this app session. Exiting LifeViz cancels waiting jobs, requests cancellation of the active job, and waits for partial output to finalize before closing. It does not resume after a restart. Let bakes finish before using **Update to Latest Release...** if you want complete videos. A crash or forced termination can leave an incomplete file. Worker processes use Windows kill-on-close containment where available, with explicit process-tree termination during teardown.

A background worker starts a fresh scene timeline. Captured settings do not include the current random simulation cells, live transport position, or active random AutoClip selection. Referenced media is not copied: keep files available and unchanged until the bake finishes. Webcam and desktop-window sources sample live inputs and may be constrained by device sharing. Unmuted enabled video audio drives reactivity; the output stays silent.

One worker has its own GPU compositor, simulation engines, media decoders, encoder, and private config/log files. It never loads or saves the editor's autosave, changes its startup-recovery marker, plays duplicate source audio, or detaches its frame pump. Temporary files for completed/cancelled jobs are removed after the worker exits. Failed jobs retain their private folder under `%TEMP%\lifeviz-bakes`; remove it manually once the problem has been diagnosed. Progress and completion travel over a process pipe, with at most one pending update, so a locked status file cannot abort a video and a slow status reader cannot stall frame production. Only scene configuration is stored for waiting jobs; no queued video frames or transcode cache are created. CPU, GPU, memory, and storage bandwidth are still shared, so a heavy bake can reduce preview FPS.

See [Rendering Pipeline](Rendering-Pipeline.md) for frame-clock and encoder details and [Build & Install](Build-and-Install.md) for the `background-bake` integration smoke.

Bakes use above-normal process and render-thread priority, matching the earlier foreground exporter. Background operation comes from the separate worker process; the renderer is no longer scheduled below other normal-priority work. This avoids a throughput regression under CPU load. Preview and bake still share hardware, so simultaneous editing can affect export speed. Updates apply to newly launched workers after restarting the app; let the current queue finish before updating.
